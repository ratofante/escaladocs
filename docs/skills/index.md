# Skills

*After this page you can name the skills that exist around `escalafy-app`, say where each one lives, and know which page to open before using or editing one.*

:::tip[In simple terms]

A skill is a recipe that Claude Code follows when you type its name as a command, such as `/daily-summary`. The recipe is a Markdown file in a folder. The first lines of the file say what the skill is for; the rest says what to do, step by step. Claude reads the first lines all the time and the rest only when the skill is used.

Some skills come from packages (OpenSpec, Stripe, Anthropic). The ones in this section are ours: written for how this team works, kept next to the code, and edited like any other file.

:::

## Catalog

| Command | Lives in | Use it when |
| --- | --- | --- |
| `/issue-research ESC-nnn` | `escalafy-app/.claude/skills/issue-research/` | Starting work on a Linear issue. Produces the research note and the decision table. |
| `/issue-plan ESC-nnn` | `escalafy-app/.claude/skills/issue-plan/` | Decisions are settled. Slices the issue into OpenSpec changes and writes the proposals. |
| `/issue-build ESC-nnn [close]` | `escalafy-app/.claude/skills/issue-build/` | Proposals are reviewed. Dispatches Opus implementers; `close` summarises and archives. |
| `/daily-summary [date]` | `~/.claude/skills/daily-summary/` | End of day. Reconstructs the day from git, OpenSpec and memory and writes the team update. |
| `/write-guide init\|chapter\|check` | `escalafy-docs/.claude/skills/write-guide/` | Writing a chaptered guide for this site. |
| `/sentry-triage [baseline]` | `escalafy-app/.claude/skills/sentry-triage/` (shared) | Runs on a schedule. Triages production errors into Linear tickets and a Slack summary. |
| `/merge-conflicts`, `/merge-conflicts-async` | `~/.claude/skills/`, `escalafy-app/.claude/skills/` (shared) | A merge or rebase stopped on conflicts. The async one runs unattended. |
| `/escalafy-ux` | `escalafy-skills/skills/design/escalafy-ux/`, linked into `~/.claude/skills/` | A flow feels clunky. Measures it and ranks findings with evidence; no code. |
| `/escalafy-design` | `escalafy-skills/skills/design/escalafy-design/`, linked into `~/.claude/skills/` | A new screen, state or component is needed. Draws iterations in Figma. |
| `/escalafy-figma-sync [audit\|apply\|promote]` | `escalafy-skills/skills/design/escalafy-figma-sync/`, linked into `~/.claude/skills/` | After a token or variant change, or to promote an approved design to the UI Kit. |
| `/ds-page-migration` | `escalafy-skills/skills/design/ds-page-migration/`, linked into `~/.claude/skills/` | An approved Figma frame must become code. Phase 1 questions, phase 2 build. |
| `/opsx:propose`, `/opsx:apply`, `/opsx:archive`, … | `escalafy-app/.claude/skills/openspec-*/` | The OpenSpec workflow itself. Generated by the OpenSpec CLI; our skills call these rather than restate them. |

"Shared" means the folder is allowlisted in `escalafy-app/.gitignore` and committed, so the team gets it. Everything else under `.claude/` is local to one machine.
